標頭歸屬：x-cache 原本是 Fastly 的，但 Byte Shield 會把它覆蓋成自己的值（例如 BYPASS），所以第 1 層讀 x-cache。 Fastly 這層改看 x-cache-hits，它沒有被覆蓋。
舊版的坑：x-proxy-cache 其實是 GitHub Pages 自己給的，不是 CDN 的。舊版把它當成第 1 層的備用標頭，才會把 GitHub 的 MISS 誤當成 CDN 的狀態。
BYPASS 的意思：Byte Shield 沒有快取這個回應，每次都回源。要看到 MISS → HIT，得先在「缓存规则」設定快取時間。
注意：這個檢測請求帶了 cache:'no-store'，只影響瀏覽器的快取，不影響 CDN。
